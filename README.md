# Research Brief Agent: Super Investing AI Innovator (Part B)

**Input:** an NSE ticker + a set of documents (uploaded in the UI or read from a folder).
**Output:** a one-page Markdown brief: Snapshot, Bull case, Bear case, Open questions, Sources.
Every line is cited and checked by code, so each claim can be traced to a source document.

## Run it

Needs Python 3.10+.

```bash
pip install -r requirements.txt

# Free Groq API key from https://console.groq.com (no card needed)
export GROQ_API_KEY="your_key"          # Windows PowerShell:  $env:GROQ_API_KEY="your_key"
export GROQ_MODEL="openai/gpt-oss-120b" # PowerShell: $env:GROQ_MODEL="openai/gpt-oss-120b"

streamlit run app.py                    # UI: upload documents + ticker, watch every step
python run.py --ticker SRVCABLE         # CLI: reads ./research_pack/, writes SRVCABLE_brief.md
python run.py --list-models             # models your key can use
```

Offline alternative: install Ollama, `ollama pull qwen2.5:7b`, then `LLM_PROVIDER=ollama`.

Every run saves its evidence in `runs/<timestamp>-<mode>/`: parsed documents, extracted claims, the cross-check
analysis, each draft, each verifier report, the final brief and `run.json` (model, repair rounds, errors left).

### Modes (used for the test log)
| Command | What it does |
|---|---|
| `python run.py --mode baseline` | Naive control: all documents in one prompt, no steps, no repair. Verified afterwards by the same checker. |
| `python run.py --no-repair` | Full 5-step agent, but the verifier only reports errors. |
| `python run.py` | Full agent with the verifier repair loop. |

## Model and why
**Used: `openai/gpt-oss-120b` on Groq's free tier.** It is free (no card), follows JSON and citation rules better
than the smaller models available on my key, and runs in the cloud, so the laptop stays idle.
- Other models on my key were speech, safety or Arabic-specific models, or had output limits too low for one request.
- The 120b model's free tier allows about 8,000 tokens per minute, so `agent/llm.py` has a small **token throttle**:
  it estimates tokens used in the last 60 seconds and pauses before a call that would exceed the cap
  (change with `TPM_BUDGET`). If a model name is rejected, the code lists the available models and auto-selects one.
- A run therefore takes a few minutes. That is the free-tier limit, not the agent's logic.
- Offline option: Ollama `qwen2.5:7b` (free, private, slower on CPU).

## How the agent thinks (5 steps)
```
documents ─▶ 0 INGEST ─▶ 1 EXTRACT ─▶ 2 CROSS-CHECK ─▶ 3 WRITE ─▶ 4 VERIFY ─▶ brief
             (code)      (LLM, per doc)  (LLM, all claims) (LLM→JSON)  (code)  ▲   │
                         + quote check                      + code adds        └───┘ repair loop
                           (code)                           citations      (MAX_REPAIR_ROUNDS in config.py)
```
0. **Ingest (code):** parse source/URL/date, compute document age vs 23 Sep 2026, flag stale / undated / future-dated,
   and give each source a trust tier (exchange filing > company-issued > media > social).
1. **Extract (LLM, one document at a time):** atomic claims, each with a *verbatim quote*, typed as fact / forecast /
   opinion / promotional. **Code checks that each quote really exists in the document; if not, the claim is discarded.**
2. **Cross-check (LLM):** finds conflicting numbers, uncorroborated claims, old data presented as current, forecasts that
   contradict results, and missing basics (cash flow, debt, promoter pledging...).
3. **Write (LLM, returns JSON):** the brief is written from the verified claims only, never from the raw documents.
   **Code adds the bullets, headings and `[S#]` tags**, so a missing citation is a visible error, not a formatting slip.
   If the cross-check found a conflict the writer left out, code adds it to Open questions (marked "added by cross-check").
4. **Verify (code, no LLM):** every line cited, every cited number really present in the cited source, length limit,
   every detected conflict raised in Open questions. On failure, the exact errors go back to the model for a rewrite.
   The **Sources section is generated by code**, so URLs and dates can never be hallucinated.

**Design decision I'm proudest of: "the model proposes, code checks."** Anything that can be verified deterministically
(quotes, citations, numbers, length, sources list) is done in plain Python, not by asking another model.

## Files
```
config.py                  settings: today's date, thresholds, providers
prompts/system_prompt.md   the agent's principles (grounding, scepticism, recency, conflicts)
prompts/*.md               one prompt per step
agent/ingest.py            step 0: parsing, staleness, trust tiers
agent/llm.py               LLM wrapper: rate-limit throttle, retries, model auto-pick
agent/pipeline.py          orchestration of the 5 steps
agent/verify.py            quote check, brief checks, final assembly
run.py / app.py            CLI / Streamlit UI (upload any .md, .txt or .pdf documents)
TEST_LOG.md                the three-run test log
```

## Known limitations
- **Numbers must match a source exactly.** The agent never computes growth or converts units. This stops invented
  figures, but it also stops useful derived checks, for example noticing that ₹1,428 crore vs ₹1,248 crore could be a
  digit transposition. A possible fix: allow numbers labelled "calculated" and verify them separately.
- **The verifier proves traceability, not good judgement.** A correctly cited but stale or superseded fact can still end
  up in the bull or bear case. The prompt tells the writer to avoid this, but it is not enforced in code.
- **Conflict detection depends on the LLM noticing the conflict.** Code only guarantees that a *detected* conflict is surfaced.
- **Source trust tiers are keyword heuristics** on the source name and URL, not a real reputation database.
- **Tested on one research pack** (Sarvottam Cables), with one model family. Scanned PDFs are not supported (no OCR).
- No live-data tool (the optional bonus).
